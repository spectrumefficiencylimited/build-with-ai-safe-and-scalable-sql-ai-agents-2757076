Use skills to inject domain knowledge into your SQL agent
The final topic in this chapter is skills. Skills are a powerful way to extend the agent's context by supplying information the model cannot reliably infer from the data alone. This can include business logic, data mappings, or domain-specific rules. In practice, a skill is a standalone markdown file that defines this knowledge in a structured way for rules, examples, or step-by-step instructions. This approach lets you modulize expertise and reduce unnecessary prompt noise. It also improves performance on complex or specialized tasks without retraining the model or outcoding logic into the agent. Using skills is optional, and you should consider them when you anticipate a higher level of complexity or ambiguity in user questions. The additional context provided by the skill enable the model resolve ambiguities and apply the appropriate business logic. Before we close this chapter, one important caveat about skills. While they are extremely useful for injecting domain knowledge, they also increase the number of tokens sent with each prompt and therefore increase cost. For that reason, skills should be used deliberately. Add them when the task truly requires extra context and avoid including them when simpler mechanism like schema inspection or distinct value extraction are sufficient. That concludes chapter two.
