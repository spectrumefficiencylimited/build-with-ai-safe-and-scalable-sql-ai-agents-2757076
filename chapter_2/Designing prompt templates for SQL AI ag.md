Designing prompt templates for SQL AI agents
Prompts play a critical role in an AI agent functionality and overall performance. A well-designed prompt template allow us to generalize the behavior of an SQL agents making it more reliable and better equipped to handle a wide range of edge cases. In this chapter, we'll walk through a few practical steps to improve and structure prompt templates so they can handle different scenarios more effectively. We also explore how to add memory to the agents, enabling user to ask a follow-up questions without having to repeatedly restate context. The goal isn't to cover every possible edge case. Instead, this chapter aims to give you the principles and the tools you need to adapt, extend, and fine-tune PROM templates for your own use cases. Throughout this course, we'll use the LangChange ecosystem to interact with LLMs via the OpenAI compatible interface and to define our PROM templates. This approach allows us to switch seamlessly between providers such as OpenAI, Google Gemini, and Entropiq by simply changing a few configuration arguments. At this stage, our goal is not to execute queries, but understanding how the PROM template is working under the hood. For this demo, we'll use the 02-01B Jupyter Notebook in the chapter two folder. A SQL agent prompt template follows the standard conversational structure and consists of two roles, system and user. The role of the system prompt is to provide the LLM with broader context about the task and to clearly define expectations for the output. Below is the baseline system prompt we will use throughout the course. Given the following SQL table, your job is to write queries giving a user request. This provides critical context the LLM needs to understand the database structure, including the available fields and their attributes. Clear, descriptive field names are especially important as they help the model accurately infer what each field represents.
