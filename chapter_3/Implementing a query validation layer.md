Implementing a query validation layer
In this lesson, we'll learn how to add a validation process for SQL queries. For this demo, we'll use the 03-03b Jupyter Notebook in the Chapter 3 folder. We'll run everything inside the course virtual environment. The goal is simple. We want a function that takes the SQL query generated by the LLM and checks whatever it uses any unauthorized SQL commands. To do this, we will use the SQLglut library. SQLglut provides tools for parsing and analyzing SQL queries in Python. We'll use its parsing capabilities to inspect each query. Then, we will determine whatever the query contains only allowed SQL statements or includes restricted ones. If the validation passes, the agent sends the query to the database handler. If it fails, the agent blocks execution and flags the query. Now, let's look at a simple implementation. We will use a function called isQueryValid. This function takes three inputs. A SQL query, a list of allowed statements, and a list of restricted statements. The function returns true only if the query contains allowed statements. If it includes restricted ones, it returns false. Next, we'll define the allowed and disallowed statements. For simplicity, we'll allow, select, with, accept, show, and describe statements. We'll restrict any statement that can modify, delete, or change access to the database. Now let's test the validation logic. We'll start with a simple query, select star from air traffic. Let's execute the above code and test if it's a valid statement. As expected, it passes validation. We will test a query that includes a drop table statement. Let's execute it. This time, the validation fails as expected. This validation step acts as a final safety check before execution by the DB handler.
