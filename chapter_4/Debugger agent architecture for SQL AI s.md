Debugger agent architecture for SQL AI systems
So far, we have seen how the different components of the SQL AI agent work together. From designing a robust prompt template to generating SQL queries with an LLM and validate it. At this point, a natural question arises. Can we apply the same LLM-driven approach to debugging runtime errors? The short answer is yes, we definitely can. In this lesson, we'll see exactly how. Here is a design diagram of the debugger agent. It follows the same approach we used earlier to generate SQL queries with the LLM. When an error occurs, the error handle triggers the debugging process. It uses a dedicated prompt template that receives the following arguments. The user's question, the failed query, the corresponding error message, and the table schema. It then sends the prompt with a debug request to the LLM, which returns a new SQL query. From this point, we return the query to the regular post-generation process, parse it, and validate it before sending it to execution. If the query execution failed again, we can repeat the process. For those reasons, embedding a memory is critical to providing the LLM with a debugging history. Let's see how it works in practice.
